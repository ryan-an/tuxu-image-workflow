# 图序 · 批量生图工作流

个人本机使用：React / TypeScript 前端，Fastify API 与后台任务队列运行在一个 Node.js 进程，SQLite 保存工作区和任务，图片保存在本地目录。无需安装 PostgreSQL 或 Docker。

## 本机启动

Windows 局域网免安装部署可使用内置 Node.js 的便携 ZIP：解压后双击「启动图序.cmd」，其他电脑通过浏览器访问。便携版固定将 SQLite、素材、日志和证书放在程序旁的 `data/`，将密码、加密主密钥和运行配置放在 `.env`；升级或改成 EXE 时只需完整保留这两个位置。打包命令为 `npm run windows:pack`（先测试并构建），使用与升级步骤见 [Windows 便携部署](docs/windows-portable.md)。

Docker、Windows ZIP/EXE 之间的数据备份、恢复和迁移步骤见 [数据备份与迁移指南](docs/data-migration.md)。

需要 Node.js 24。首次安装和构建：

```powershell
npm install
npm run build
npm start
```

已经构建后，双击 `启动图序.cmd` 即可启动。打开 http://127.0.0.1:3001，进入独立的 `/login` 登录页，默认团队管理员用户名为 `admin`，初始密码为 `admin`。首次启动自动生成 `.env` 和加密主密钥；终端不输出密码。后续启动保留配置，可在 `.env` 的 `APP_PASSWORD` 修改所有者密码并重启。登录保持 12 小时，未过期会话在服务重启后保留；退出、禁用、变更角色或重置密码会撤销相应会话。在页面“设置”分别填写豆包对话 API Key（火山方舟）和 Grsai 生图 API Key，两套密钥独立加密保存，保存不会自动发起生成。

默认 `REQUIRE_HTTPS=false`，本机、局域网、Docker 和公网 IP 均可继续通过 HTTP 使用，不需要证书。普通 Node 服务供其他设备访问时设置 `HOST=0.0.0.0`。以后需要强制 HTTPS 时，配好证书或代理，再将开关设为 `true` 并重启，无需重建前端。没有域名也可选用 `npm run setup:https` 生成本地/IP 证书。完整配置见 [登录与 HTTPS](docs/transport-security.md)。

一个管理员对应一个团队和独立工作区。开发者先构建并重启新版服务，再执行 `npm run teams -- create team_b "B团队"`，按终端提示设置密码；新管理员登录后进入空工作区。`npm run teams -- list` 查看团队，`npm run teams -- reset-password team_b` 重置管理员密码。默认 `admin` 继续管理原团队，使用 `APP_PASSWORD`；新团队管理员密码由部署命令管理，不受 `APP_PASSWORD` 影响。登录用户名全站唯一，无需额外选择团队。

每个账号可创建自己的工作区，也可通过邀请加入其他空间；角色在各空间内独立生效。左侧产品集合上方可切换空间或进入“工作区管理”，所有者从“成员管理”邀请编辑者和查看者，支持所有权转让、归档和恢复。已有账号确认加入时保留密码及原有空间；新账号通过有效邀请设置密码，不开放公共注册。成员移除只影响当前空间。各空间的产品、素材、对话、任务、API Key 和用量独立；新成员默认不限额度，额度框暂不可编辑，只有成功生图计数。分享邀请前请使用成员能够访问的站点地址。详见 [账号、工作区与协作权限](docs/accounts.md)。

对话与整套提示词分析默认使用 `doubao-seed-2-1-pro-260915`，通过火山方舟 Responses API 接入，可在“设置”填写其他豆包 Model ID 或 Endpoint ID。先在火山方舟开通所选模型服务。图片生成仍使用原有 Grsai 模型；只咨询或分析提示词时不需要生图密钥。已有 Grsai 密钥会保留，新提交的分析任务使用豆包，原队列任务保留提交时的服务配置。

右下角“豆包”支持多轮咨询。每张卡片的“问豆包”会自动附带产品资料、当前提示词、实拍图、对标图和选用的生成结果（未选用时取最新版本），方便评估图片和优化提示词。对话按产品和卡片独立保存在服务端 SQLite 中，刷新、重新登录或重启服务后可继续；发送问题时会读取当前对话的近期历史供模型参考。输入区的“清空对话”会删除当前卡片或当前产品咨询的全部服务端对话历史，其他卡片的记录保留；回复中需先停止再清空。发送使用向上箭头图标，停止使用红色方块图标。失败、中断的问题也会保存，可手动重试；读取记录不会调用模型。每次咨询最多附带 4 张实拍、4 张对标及 1 张结果图。咨询不会自动覆盖提示词或启动生图。完整的 data 目录备份包含对话，页面工作流导出的 JSON/ZIP 目前只包含工作流资料。

豆包回复采用端到端 SSE 流式传输：后端收到文本事件即转发，页面逐段解析 Markdown，支持标题、列表、表格、引用及代码块。停止或断线会保存已收到的部分回复；刷新可查看。助手入口、窗口和回复头像使用豆包官网公开提供的官方头像资源。

## 数据与恢复

卡片参考图（对标图）为可选资料，单张、整套提示词和图片生成均允许部分或全部位置未上传参考图。没有参考图的位置会依据产品资料、实拍图、当前要求和图片类型自主设计。

产品资料旁可随时打开「整套提示词要求」，直接在完整文本框中自由编辑，支持放大、查找替换和撤销替换。未保存草稿按账号、工作区和产品保留在当前浏览器，关闭或刷新后可继续，也可恢复已保存内容。可将正文命名存为模板，在其他产品中套用，支持更新、重命名、另存和删除；模板随工作区同步及备份，套用后仍需点击「保存当前产品要求」才生效。修改或删除模板不会改变已保存的产品要求。每个产品默认沿用原有共用要求，更改用于下一次生成提示词，已排队任务、已有提示词和图片保留。

- `data/workspace.sqlite`：产品、提示词、任务、结果记录和加密后的平台密钥。
- `data/assets/`：上传素材与生成图片。
- `.env`：端口、登录密码与加密主密钥。请保留此文件，否则无法解密旧平台密钥。

SQLite 使用 WAL、事务和外键约束。生图请求支持配置并发；数据库写入由短事务串行完成。关闭网页后后台继续执行，关闭服务后重新启动可以恢复已持久化任务。已获得平台任务 ID 的任务继续查询原 ID；提交中断且无法判断平台是否受理时，需要在队列里核对，避免重复付费。

完整备份：停止应用，再复制整个 `data` 目录和 `.env`。运行中不能只复制主数据库文件而忽略 WAL。页面的工作流备份包含图片，可导入新的空工作区，不包含平台密钥。未保存的编辑草稿请先保存。

首次打开空服务端工作区，会读取当前浏览器里的旧 v2 工作区并导入；旧 IndexedDB 数据保留。未完成旧任务停止，检查后可恢复。新用户不会自动创建演示产品。

## 开发与验证

后台日志在启动终端实时显示，同时追加到 `data/logs/server.log`。在 PowerShell 中运行 `Get-Content .\data\logs\server.log -Tail 50 -Wait` 可持续查看。任务错误记录包含任务 ID、阶段、模型、耗时和底层网络错误码，不记录 API Key、请求正文或图片内容。页面“执行队列”的明细也可查看每条任务错误。

运行 `npm run dev:api`，另一个终端运行 `npm run dev`，前端 5173 的 API 请求转发到 3001。后端修改后重新启动。正式运行使用 `npm run build` 后的 `npm start`，同一个进程提供页面、API 和后台队列。

```powershell
npm test
npm run test:unit
npm run test:integration
npm run build
```

测试使用隔离的真实 SQLite 文件和模拟平台，验证事务、并发领取、任务恢复、文件重开、图片与凭据持久化，不修改个人数据或调用付费接口。

测试统一放在 `tests/`，按 `unit`、`integration`、`e2e`、`support` 和 `legacy` 分层，目录约定见 [测试说明](tests/README.md)。`npm test` 运行单测与集成测试，浏览器回归在构建后单独执行：

```powershell
$env:PLAYWRIGHT_MODULE = '你的 Playwright 模块目录'
$env:CHROME_PATH = '你的 chrome.exe 路径'
npm run test:e2e
```

覆盖登录、编辑草稿、提示词保存、后台生成后重开页面、选图、ZIP、表格复用、工作流备份及豆包卡片咨询。真实调用需要配置对应的豆包或 Grsai API Key。

## 可选 Docker

当前版本和图文更新说明见工作台右上角「账号菜单 → 更新日志」，也可直接访问 `/updates/`。新部署包自动递增版本并保留历史包；维护方式见 [版本与更新日志](docs/releases/README.md)。

先运行 `npm run setup` 生成配置，再运行 `docker compose up --build -d`。只有一个应用容器和一个数据卷，访问地址相同。外网访问需要 HTTPS 反向代理。

云服务器无需上传业务源码：本机运行 `npm run docker:pack` 编译并生成运行包（本机不需要 Docker），再运行 `npm run docker:deploy -- --host root@服务器IP --domain 你的域名`，JS 脚本自动上传、在服务器 Docker 内安装运行依赖并组装镜像、生成配置和启动。服务器只需 Docker 和 Compose，不需要 Node.js；首次随机生成密码，后续保留数据与加密密钥。`npm run docker:image` 保留本机 Docker 完整镜像打包模式。平台选择、已有反向代理和无域名访问见 [部署说明](docs/docker-deployment.md)。

模块职责见 [架构文档](docs/architecture.md)，前端维护见 [前端架构](docs/frontend.md)。旧原型记录见 [原型记录](docs/legacy-prototype.md)。`npm run dev:demo` 仅用于旧原型兼容验证。
