# 图序 · 批量生图工作流

个人本机使用：React / TypeScript 前端，Fastify API 与后台任务队列运行在一个 Node.js 进程，SQLite 保存工作区和任务，图片保存在本地目录。无需安装 PostgreSQL 或 Docker。

## 本机启动

需要 Node.js 24。首次安装和构建：

```powershell
npm install
npm run build
npm start
```

已经构建后，双击 `启动图序.cmd` 即可启动。打开 http://127.0.0.1:3001，进入独立的 `/login` 登录页，默认用户名和密码均为 `admin`。首次启动自动生成 `.env` 和加密主密钥，终端显示登录密码；后续启动保留配置，可在 `.env` 的 `APP_PASSWORD` 修改登录密码。登录保持 12 小时，工作台右上角可退出登录；服务重启后需重新登录。在页面“设置”分别填写豆包对话 API Key（火山方舟）和 Grsai 生图 API Key，两套密钥独立加密保存，保存不会自动发起生成。

对话与整套提示词分析默认使用 `doubao-seed-2-1-pro-260915`，通过火山方舟 Responses API 接入，可在“设置”填写其他豆包 Model ID 或 Endpoint ID。先在火山方舟开通所选模型服务。图片生成仍使用原有 Grsai 模型；只咨询或分析提示词时不需要生图密钥。已有 Grsai 密钥会保留，新提交的分析任务使用豆包，原队列任务保留提交时的服务配置。

右下角“豆包”支持多轮咨询。每张卡片的“问豆包”会自动附带产品资料、当前提示词、实拍图、对标图和选用的生成结果（未选用时取最新版本），方便评估图片和优化提示词。对话按产品和卡片独立保存在服务端 SQLite 中，刷新、重新登录或重启服务后可继续；发送问题时会读取当前对话的近期历史供模型参考。输入区的“清空对话”会删除当前卡片或当前产品咨询的全部服务端对话历史，其他卡片的记录保留；回复中需先停止再清空。发送使用向上箭头图标，停止使用红色方块图标。失败、中断的问题也会保存，可手动重试；读取记录不会调用模型。每次咨询最多附带 4 张实拍、4 张对标及 1 张结果图。咨询不会自动覆盖提示词或启动生图。完整的 data 目录备份包含对话，页面工作流导出的 JSON/ZIP 目前只包含工作流资料。

豆包回复采用端到端 SSE 流式传输：后端收到文本事件即转发，页面逐段解析 Markdown，支持标题、列表、表格、引用及代码块。停止或断线会保存已收到的部分回复；刷新可查看。助手入口、窗口和回复头像使用豆包官网公开提供的官方头像资源。

## 数据与恢复

产品资料旁可随时打开「整套提示词要求」，同一资料栏提供带数量的实拍图管理按钮。每个产品默认沿用原有共用要求，编辑并保存后只对当前产品生效；可恢复默认要求，也可取消未保存修改。更改用于下一次生成提示词，已排队任务、已有提示词和图片保留。

- `data/workspace.sqlite`：产品、提示词、任务、结果记录和加密后的平台密钥。
- `data/assets/`：上传素材与生成图片。
- `.env`：端口、登录密码与加密主密钥。请保留此文件，否则无法解密旧平台密钥。

SQLite 使用 WAL、事务和外键约束。生图请求支持配置并发；数据库写入由短事务串行完成。关闭网页后后台继续执行，关闭服务后重新启动可以恢复已持久化任务。已获得平台任务 ID 的任务继续查询原 ID；提交中断且无法判断平台是否受理时，需要在队列里核对，避免重复付费。

完整备份：停止应用，再复制整个 `data` 目录和 `.env`。运行中不能只复制主数据库文件而忽略 WAL。页面的工作流备份包含图片，可导入新的空工作区，不包含平台密钥。未保存的编辑草稿请先保存。

首次打开空服务端工作区，会读取当前浏览器里的旧 v2 工作区并导入；旧 IndexedDB 数据保留。未完成旧任务停止，检查后可恢复。新用户不会自动创建演示产品。

## 开发与验证

后台日志在启动终端实时显示，同时追加到 `data/logs/server.log`。在 PowerShell 中运行 `Get-Content .\data\logs\server.log -Tail 50 -Wait` 可持续查看。任务错误记录包含任务 ID、阶段、模型、耗时和底层网络错误码，不记录 API Key、请求正文或图片内容。页面“执行队列”的明细也可查看每条任务错误。

运行 `npm run dev:api`，另一个终端运行 `npm run dev`，前端 5173 的 API 请求转发到 3001。后端修改后重新启动。正式运行使用 `npm run build` 后的 `npm start`，同一个进程提供页面、API 和后台队列。

```powershell
npm test
npm run test:unit
npm run test:integration
npm run build
```

测试使用隔离的真实 SQLite 文件和模拟平台，验证事务、并发领取、任务恢复、文件重开、图片与凭据持久化，不修改个人数据或调用付费接口。

测试统一放在 `tests/`，按 `unit`、`integration`、`e2e`、`support` 和 `legacy` 分层，目录约定见 [测试说明](tests/README.md)。`npm test` 运行单测与集成测试，浏览器回归在构建后单独执行：

```powershell
$env:PLAYWRIGHT_MODULE = '你的 Playwright 模块目录'
$env:CHROME_PATH = '你的 chrome.exe 路径'
npm run test:e2e
```

覆盖登录、编辑草稿、提示词保存、后台生成后重开页面、选图、ZIP、表格复用、工作流备份及豆包卡片咨询。真实调用需要配置对应的豆包或 Grsai API Key。

## 可选 Docker

先运行 `npm run setup` 生成配置，再运行 `docker compose up --build -d`。只有一个应用容器和一个数据卷，访问地址相同。外网访问需要 HTTPS 反向代理。

模块职责见 [架构文档](docs/architecture.md)，前端维护见 [前端架构](docs/frontend.md)。旧原型记录见 [原型记录](docs/legacy-prototype.md)。`npm run dev:demo` 仅用于旧原型兼容验证。
