# 账号、工作区与协作权限

## 产品模型

账号代表一个人，负责用户名、密码、个人名称和全局登录会话。一个账号可以加入多个工作区，工作区成员关系决定该账号在某个空间的角色。没有公共注册入口；新账号通过部署端或有效邀请创建。

工作区统一承载个人创作与团队协作，不维护两套空间类型。所有已登录账号都能新建空工作区，并自动成为其所有者；在其他空间是编辑者或查看者不影响创建能力。每个工作区保留一位所有者，允许转让给已加入的有效成员；所有者先转让再退出。

| 角色   | 当前工作区内的能力                                                        |
| ------ | ------------------------------------------------------------------------- |
| 所有者 | 管理成员、邀请、API Key、模型、全部资料，以及空间名称、归档和所有权 |
| 编辑者 | 创建和编辑产品、素材与提示词，调整个人生图模型与生成参数，发起分析、生图和对话，选图和导出；不管理 API Key |
| 查看者 | 查看资料、提示词与结果，下载和导出；下载勾选只影响自己的页面              |

产品、素材、密钥、任务、对话、同步游标和生成用量始终按工作区隔离。工作区切换不会复制资料、继承其他空间密钥或停止后台任务。新建工作区需要独立配置 API Key。

所有者和编辑者均有「模型配置」入口。生图模型、比例、分辨率、GPT 尺寸和质量按用户及工作区分别保存，只影响本人任务。豆包对话模型、运行方式和生图节点为工作区共享配置，仅所有者可见并可修改；编辑者的表单不渲染或提交这些字段，接口也会拒绝越权修改。查看者不能修改配置。任务入队时冻结当时的共享配置和发起人的个人生图参数，后续修改或由其他成员重试均沿用原任务快照。

「API Key」是独立入口，保存当前工作区成员共用的服务密钥，仅所有者可见并可修改或清除。`POST /api/workflow/credentials` 只处理密钥字段；`GET/POST /api/workflow/settings` 读取当前工作区的有效配置，按字段权限保存共享配置或请求账号的个人生图参数。旧页面向 settings 接口提交密钥的兼容请求仍需所有者权限，混合请求失败时不保存任何设置。写事务重新验证当前成员角色，账号和工作区范围取自认证上下文。

迁移 017 将原工作区模型参数复制为既有成员各自的初始配置；018 将当前所有者原有的豆包模型和节点选择转为工作区配置，移除个人记录中的共享字段，保留各自生图参数、共用密钥和任务快照。新成员首次保存前使用该工作区保留的旧生图默认参数。个人生图配置记录不进入工作区文档同步和页面业务备份；完整数据库备份保留这些记录。

## 页面和流程

- 左侧产品集合上方显示当前工作区，点击展开切换列表。列表展示角色、成员数和当前选中状态，底部保留管理入口，最后一项是“新建工作区”。
- 工作区管理在主界面内打开，保留当前产品集合和导航，显示当前所在空间；点击产品或“返回工作台”即可继续创作。账号没有可访问空间时才使用独立管理页。
- 新建使用弹窗，只需名称，成功后直接进入新空间；取消不影响当前空间。管理页支持重命名、归档、恢复及退出。归档保留资料并暂停所有成员访问，归档前需完成或取消未结束任务；首版不提供彻底删除。
- 所有者从“成员管理”生成一个编辑者或查看者的分享邀请，链接 7 天有效、单次使用，也可按用户名邀请指定账号。
- 已有账号登录并确认加入，保留原密码和原有工作区。没有账号的人通过有效邀请选择用户名并设置密码；指定新账号的邀请沿用预先填写的用户名。
- 邀请只能在生成时复制完整链接，列表可撤销；重新邀请仅适用于待加入成员，不会重置任何人的密码。
- 禁用或移除成员只作用于当前空间，不撤销全局登录、不删除个人账号，也不改变其他空间的身份。空间内名称是成员称呼，不修改全局个人名称。
- 所有权转让后，原所有者成为编辑者。最后一位所有者不能直接退出、被移除或被禁用。

分享邀请前应通过成员能访问的站点地址打开页面；默认支持 HTTP，只有启用 `REQUIRE_HTTPS=true` 时要求 HTTPS。开关、证书和代理配置见 [登录与 HTTPS](transport-security.md)。令牌位于 URL fragment，以 POST 发送服务端；密码及令牌均不保存在 localStorage。

## 认证和工作区上下文

`account_sessions` 只绑定全局账号。`authentication.ts` 每次请求先解析账号，再根据本页的 `X-Workspace-Id` 查有效成员关系，得到当前工作区角色；请求体无法改变工作区范围。`X-Account-Id` 防止另一标签切换登录账号后，旧页面误操作新身份。

每个标签的 URL 固定自己的 `?workspace=<id>`。切换先等待控制器保存草稿，然后完整导航，避免旧请求、表格实例或助手状态泄漏进新空间。不同标签可以同时打开不同空间。管理页和个人密码属于全局账号范围，路由显式标记 `config.accountOnly: true`；创建工作区不能套用某个空间的编辑权限。

业务接口默认只读 GET，写请求默认要求编辑权限；空间管理接口显式 `config.permission: "manage"`。所有者写操作在事务内再次验证身份。无有效成员关系、被禁用或空间归档后拒绝访问。SSE 携带空间和预期账号，并定期复查成员访问资格。图片原生请求根据资产 ID 找到所属空间，再验证账号成员关系；显式空间头存在时仍需匹配该资产。

## 数据和模块边界

| 模块                                                  | 职责                                                         |
| ----------------------------------------------------- | ------------------------------------------------------------ |
| `shared/access.ts`                                    | 全局身份、工作区上下文、成员、空间和邀请类型，通用角色权限   |
| `accounts.ts`                                         | 全局凭据、会话、修改密码及部署端账号恢复                     |
| `members.ts`                                          | 指定工作区的成员列表、空间内称呼、权限、禁用、移除及邀请管理 |
| `invitations.ts`                                      | 邀请校验、已有账号确认、新账号激活和原子单次兑换             |
| `workspace-directory.ts`                              | 空间列表、成员上下文、创建、重命名、归档、退出和所有权转让   |
| `member-routes.ts`、`workspace-routes.ts`             | HTTP 契约与参数校验，不实现独立业务规则                      |
| `workspaces.ts`、`workspace-workers.ts`               | 不可变空间范围的业务运行时与后台执行器                       |
| `account-usage.ts`                                    | 每个空间成员的图片容量检查、成功记账和月统计                 |
| `provisioning.ts`、`scripts/teams.mjs`                | 部署端批量创建账号及其首个工作区，列出所有者和恢复账号       |
| `src/services/members.ts`、`workspaces.ts`            | HTTP 客户端及空间导航                                        |
| `src/application/use-members.ts`、`use-workspaces.ts` | 页面用例、请求状态与错误协调                                 |
| `src/ui/members`、`src/ui/workspaces`                 | 成员与空间页面展示                                           |

核心表：`accounts` 保存全局身份；`workspace_members(workspace_id,account_id)` 保存角色、成员状态、空间内称呼和额度；`workspace_invitations` 独立记录邀请，可以绑定已有账号或允许新成员领取。唯一索引保证每个空间仅一位所有者，转让时在同一个事务先降级原所有者再提升新所有者。

成员的 `accepted_at` 独立记录加入确认；禁用后重新启用不会把待接受邀请变成已加入成员。被禁用成员不能使用通用邀请绕过禁用。所有者、成员和业务写入共用 `workspace-access.ts` 的权限事实，事务中重新校验有效成员及空间归档状态。

## 成功生图用量

按工作区、成员和北京时间自然月统计。结果下载并保存成功才计 1 次，归属最近重试者或原发起人，以完成月份记账。提示词分析、对话、失败和取消不计数；同一图片任务的恢复、查询和重复命令不重复计数。额度框仅展示、不可编辑，新成员默认不限。

如果部署端设置有限额度，入队与重试事务检查成功数加待完成图片数，防止并发越额；待完成任务不增加用量。图片、完成状态、成功明细和月统计同事务保存。成员退出或被移除不会删除其历史用量，重新加入也不会清零。

## 迁移和部署管理

只追加迁移，禁止修改已执行 SQL。011 将原账号上的工作区、角色、状态和额度迁移至成员关系，保留账号 ID、密码哈希、有效会话及旧邀请；012 补充分离的邀请接受状态。010 的成功图片记账保留原空间归属，已从工作流删除的任务明细也能迁移。原产品、资产、任务和命令无需搬动。

默认 `admin` 仍通过 `APP_PASSWORD` 恢复密码，但启动不会夺回已经转让的默认空间所有权。其他账号可自行修改密码，开发者可在部署端恢复；这些能力与工作区角色独立。

```powershell
npm run teams -- create team_b "B团队"
npm run teams -- list
npm run teams -- reset-password team_b
```

创建与恢复命令不回显密码；自动化可使用 `TUXU_TEAM_PASSWORD`。`create` 是创建新账号及其首个工作区的部署便利操作，普通用户的其他空间从页面创建。完整数据备份包含身份、成员、会话、邀请与用量；页面工作流 JSON/ZIP 只备份业务资料。

回归覆盖 `multi-workspace.test.ts`、`accounts.test.ts`、`workspace-isolation.test.ts`、`team-migration.test.ts`、`authentication.test.ts` 及 `workspace-management-browser.test.ts` 等。夹具使用隔离 SQLite、素材目录和模拟平台，不访问个人数据或付费接口。

## 超级管理台

固定默认账号 admin 拥有系统角色 `super_admin`，从顶栏账号菜单进入「超级管理台」（`/admin`）。普通账号没有入口，直接调用后台接口也会被拒绝。首版不开放超级管理员任命或永久删除账号、工作区；admin 密码继续由 `APP_PASSWORD` 配置管理，不能全局禁用该账号。

用户管理支持搜索、状态筛选与分页，可创建不附带工作区的账号，查看全局资料与各工作区成员身份、编辑个人名称、重置密码、强制下线及全局启停。全局禁用撤销会话与定向邀请，阻止登录和新请求；不会改写工作区成员关系或转让所有权，已排队任务继续执行。启用不会恢复被撤销的邀请或被禁用的成员关系。待激活账号继续通过邀请激活。重置密码同事务撤销全部会话，强制下线只撤销会话。

用户详情另提供「删除账号」：输入完整用户名确认，撤销会话和定向邀请，将账号及全部成员关系标记为已删除，并从用户与成员列表移除。拥有工作区（含已归档空间）的账号须先转让全部所有权，默认 admin 不可删除。采用逻辑删除保留历史归属、产品、图片、任务、用量和审计，已有任务继续完成；没有恢复入口，用户名保留且不可重用。普通有效账号、已禁用账号与待激活账号均可按此规则删除；删除后的邀请不能激活原账号。

工作区管理展示全部空间，支持指定有效账号为所有者创建、重命名、归档恢复、转让所有权和维护成员与邀请。转让目标必须是已经接受邀请的有效成员，同事务保留唯一所有者。归档前仍须完成或取消所有未结束任务；归档后管理员可读取资料，恢复后才能修改或发起任务。

从工作区详情「进入工作区」打开 `/?workspace=<id>&admin=1`。页面持续显示「超级管理模式」、工作区及真实操作者，并可返回管理台。管理模式由服务端重新验证系统角色，admin 不必加入成员列表，不会成为隐含所有者。多标签页分别绑定工作区，HTTP、SSE 和图片下载使用一致的服务端权限。原生图片请求根据资产所属空间验证身份；显式工作区仍须与资产归属一致。

管理员发起和重试的任务保留真实身份，使用目标空间的密钥及冻结模型参数；管理模式成功生图不占普通成员额度，按北京时间自然月单独统计「管理员操作」，并计入空间总量。管理员个人生图偏好独立保存，无需创建成员记录；原有任务与成员用量不改变归属。

全局操作记录支持按目标、操作类型与日期筛选和分页，包含北京时间、操作者、目标、结果及请求 ID。成功管理写入与审计同事务提交，失败仅记录脱敏错误码。前后差异按字段白名单记录，密码、密钥、Cookie 与邀请令牌不进入日志。业务资料修改沿用空间活动记录。

迁移 019 为账号追加 `system_role`，只将固定 `OWNER_ID` 初始化为超级管理员，新增管理审计、管理员个人生成配置与管理模式用量表。原有账号、会话、成员、密钥和工作区资料保留；升级后重启服务并刷新浏览器。设计与验收约定见 [超级管理台设计方案](admin-console-design.md)。
