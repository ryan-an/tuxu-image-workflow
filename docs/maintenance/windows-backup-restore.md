# Windows 备份恢复（维护者）

此文档供维护者使用，不随 Windows 更新包附带，不提供客户恢复按钮。恢复操作会回到快照时刻，之后新增或修改的数据不会包含在旧快照中。

## 选择快照

- 手动备份：`data/backups/manual-时间-标识/`，包含 `data/`、`.env`、`update.json`，不含程序。
- 更新备份：`data/backups/update-时间-标识/`，还包含 `program/`，保存更新前被替换的程序项。
- 仅使用状态文件 `update.json` 中 `state` 为 `complete` 的完整快照；失败、中断或无法识别的目录应先人工排查。
- 手动快照记录当时安装版本及构建标识；更新快照记录的是目标更新版本，恢复旧程序时应以 `program/manifest.json` 的版本及构建标识为准。

## 恢复步骤

1. 保存编辑并等待生成结束，从图序托盘菜单选择「退出图序并停止服务」，同时关闭更新工具。恢复期间不要启动图序。
2. 将选中的整个快照复制到程序目录之外的安全位置。备份原本位于当前 `data` 内，先移走可避免改名数据目录后找不到它。
3. 将当前整个 `data/` 和根目录 `.env` 改名另存，保留现场，切勿直接删除。确认磁盘空间足够。
4. 把快照内的 `data/` 复制为程序根目录下新的 `data/`，将快照的 `.env` 复制到程序根目录。使用快照原配置及原 `CREDENTIAL_SECRET`；数据库、WAL/SHM 和素材必须来自同一快照，不能合并覆盖到旧数据目录。
5. 使用与该数据库快照匹配的程序版本。手动快照不含程序，需要保留当时的完整便携包；更新回退可使用 `program/` 中的旧程序项替换对应程序项，或使用匹配的旧完整便携包。不要把旧程序与已升级的数据库混用，也不要未经确认把旧快照直接交给任意新版程序。
6. 启动图序，检查登录、工作区、图片与平台密钥可用性；确认恢复完成前保留原现场副本。恢复失败时先退出服务，再从现场副本整体还原，避免继续写入。

手动备份与自动更新备份共用最近 2 份成功快照的保留额度，失败或未知快照不自动删除。恢复、回退前应把所需快照单独保存到其他设备；同盘快照不能防范磁盘损坏。
