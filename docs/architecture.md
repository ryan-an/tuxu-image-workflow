# 生产架构与维护边界

前端页面和弹窗已迁移到 React / TypeScript 组件，应用控制器负责连接状态、业务操作与接口。业务适配层保留 JavaScript，沿用已有数据与表格契约。后端保持现有模块化单体，不继续增加服务或存储层次；真实平台联调仍需在目标环境验证。

## 目录结构与依赖方向

```text
src/
  app.tsx            React 入口
  ui/                页面、组件、弹窗与样式
  application/       用例协调、界面状态与生命周期
  services/          HTTP、工作区同步与远端队列客户端
  integrations/      Univer、剪贴板、文件导出与本机存储适配
  view-models/       产品分页、缩略图与队列展示数据
  demo/              旧原型、演示数据与浏览器队列
shared/              前后端共用的产品、提示词和平台配置规则
server/
  production/        生产 API、业务用例、Worker、持久化与平台适配
  demo/              仅演示模式使用的 Vite 接口插件
tests/
  unit/              单元测试
  integration/       API、数据库、Worker 及兼容集成测试
  e2e/               真实浏览器回归
  support/           测试夹具和模拟平台
  legacy/            旧原型手工验证脚本
scripts/             启动、构建、测试运行器与诊断工具
docs/                架构和使用文档
```

前端由 UI 经应用控制器调用服务与适配器，通用规则直接引用 `shared/`，不再经 `src/` 的转发文件。`view-models/` 负责展示数据计算，不发起平台请求。演示实现集中在 `demo/`，应用只在演示模式动态加载浏览器队列。生产服务继续使用现有模块化单体边界。

所有测试与夹具只能放在 `tests/`，不得反向被业务模块引用；生产构建排除该目录，测试构建输出到 `build-test/tests/`。新增文件与运行方式见 [测试目录约定](../tests/README.md)。

## 运行结构

采用模块化单体。API、Worker 共用领域模块和 SQLite，在同一个 Node.js 进程运行。Vite 仅负责前端开发与构建；生产 HTTP 服务由 Fastify 提供。

浏览器 → API → SQLite / 素材存储；Worker → 平台适配器 → Grsai。

浏览器轮询服务端任务状态。任务不会依赖网页是否打开。SQLite 是业务事实来源，IndexedDB 仅用于读取旧数据迁移，生产新数据不再写回原型快照。

生产首屏使用 `workspace-loading.ts` 的精简读取：先加载产品摘要和必要任务状态，再按需读取当前产品详情。工作表在使用时读取，任务历史继续分页；同步按客户端已加载的范围返回详情，其余产品只返回摘要，编辑保存按本次涉及范围返回数据。未加载的产品和表格不参与编辑差异，备份单独读取完整记录。HTTP 文本响应启用 Brotli/gzip，带内容哈希的静态资源长期缓存。详见 [加载性能与部署验证](loading-performance.md)。

编辑保存按差异中的产品 ID 读取、校验和写回涉及的产品，不加载任务历史；未修改的产品和工作区字段不写入。普通产品编辑不读取工作表快照，工作区字段使用 SQL JSON 路径局部更新，保留其他字段。权限、资料校验、产品编号唯一性、实际前值的操作记录及数据写入仍在同一短事务内完成；同字段按提交顺序生效，表格继续保留单元格合并规则。

产品资料或图片位置校验失败返回 HTTP 400，并在错误文字中标出产品编号及具体字段或位置问题。诊断日志仅记录请求标识、有效产品标识、错误类型和位置数量，不记录编号、名称、产品资料、提示词或图片内容。实拍图数量不参与必填校验，空字符串主图和空实拍图列表均可保存；图片字段的数据格式仍需有效。保存失败时整笔事务回滚，浏览器保留草稿供修改后重试。

`shared/product-validation.js` 维护产品编号、名称、资料和生成要求的字段规则。产品表单提交和服务端保存引用同一套资料校验，表格解析复用编号校验。编号允许内部换行和制表符，不因控制字符拒绝保存；有效文件名仅在下载时转换，业务记录中保留原编号。实拍图仍可留空。

自定义提示词模板是工作区可复用的文本来源。保存产品要求时，在同一编辑事务内写入 `promptRequirements` 正文与 `promptTemplateId` 来源标识；有来源模板时，即使正文与默认相同也保存独立正文，之后模板或默认要求变化不会替换该产品的内容。来源模板删除不级联清除产品要求。旧产品缺少来源标识时仍保留原正文或沿用默认要求，不推测模板关联。前端草稿同时保存模板选择，服务端按产品返回来源标识。有效要求为空或只有空白时，禁止创建需要分析的任务，已有提示词直接生图仍使用已保存提示词。

新客户端在 `PATCH /api/workspace` 发送 `x-workspace-result: delta`，响应包含 `editResult: "delta"`、本次编辑涉及的 `products`、涉及的工作区字段 `document` 和提交时的 `cursor`，不附带任务列表。重复提交相同内容时仍返回涉及数据的当前值，但不重复写入，避免客户端恢复成较旧的基线。前端将结果合入现有基线并保留请求期间新输入的草稿。该响应没有涵盖其他实体的全部变更，因此不能用其 `cursor` 推进增量同步游标；下一次同步仍从原游标读取，避免漏掉其他成员修改、删除或后台任务结果。未声明该响应方式的旧页面继续获得原工作区响应。协作修改通知在 100ms 窗口内合并，通知只在事务成功提交后安排。

表格解析的新产品按 `products/<id>` 提交完整可编辑记录及全部十个图片位置，与解析后的表格修改在同一事务保存；增量确认响应不裁剪新建产品的字段。前端将解析结果暂存为待提交编辑，只有保存成功才合入可见工作区，失败时保留源表格草稿。产品编号是业务标识，允许空格、星号、斜杠等可显示字符；文件系统限制只在下载文件名和 ZIP 目录名处处理，不能反向限制产品资料。ZIP 对转换后重名的目录追加序号，避免覆盖其他产品的图片。

整套分析的增量文本通过同源、登录保护的 SSE 推送至浏览器。后端解析已收到的 JSON 字符串，按图片角色生成只读预览，节流持久化到任务记录；刷新可恢复草稿。进度写入不释放任务租约，不修改正式提示词。只有完整响应通过整套契约校验后，才保存正式提示词及历史。完成或断线后仍以工作区接口同步最终状态。

分析进度不再按 300ms 跳过更新，数据库草稿仍约每秒保存一次，最终正文立即保存。`analysis-stream.ts` 串行校验身份后发送 SSE，遇到 socket 背压等待 `drain`，期间每个任务只保留最新累计快照；阶段信息与正文合并，完成事件替代旧快照。不再因 `write` 返回 false 主动断开连接；客户端直接展示收到的正文，不额外排队逐字播放。

单张和整套分析共用 `shared/prompt-suite.js` 的 `ANALYSIS_SYSTEM_PROMPT`，以独立的首条 `system` 消息发送，要求完整遵循用户条件、充分展开、依据实际资料并核对参数。在用户指定的整体结构内，各部分按主题分段，同一部分含多个主题时用简短小标题或标签逐项换行；标签由模型根据内容概括，同级内容保持格式一致，文案与数据集中列明，不规定具体小项。产品实际要求、资料、图片和返回契约继续放在 `user` 消息中。生产、演示及旧 Chat 协议的分析路径使用同一系统提示词；豆包咨询保留其工作台助手设定，生图请求使用保存的卡片提示词。

分析返回契约为 `images: [{ role, prompt, photoIndices }]`，每个 `prompt` 是模型直接编写的完整提示词。用户要求四部分时，由模型自行组织四部分及其标题、顺序、文案、重复内容与指定末句；程序不再拆分 `style`、`layout`、`copy`、`thirdPart`、`fourthPart`，也不添加标题或拼接正文。实时预览仅解码对应 `prompt` 字符串的已返回部分，完整响应直接保存同一字符串，保留首尾空白与换行。用户对图上文字的词数限制不作为完整作图说明的长度限制。旧提示词及历史记录保留，无需迁移；旧分段响应缺少完整 `prompt` 时拒绝保存，不回退拼接。

豆包 Responses API 的整套分析和咨询统一发送 `thinking: { type: "disabled" }` 关闭深度思考，直接生成回复正文。流式解析仅收集 `response.output_text.delta` 与完成事件中的正式消息正文，思考摘要不进入提示词、咨询正文或实时预览。请求参数不改写用户要求，已完成任务不会自动重新执行。

完整分析响应在结构解析前强制保存最终草稿和原始文本，绕过进度节流，避免最后一段丢失。服务端只检查 JSON、角色数量和必要字段结构，不检查提示词的词数、语言、尺寸、数量或品牌内容，也不生成内容提醒。结构解析失败保存规则代码和卡片角色，页面直接显示原因；完成日志记录提示词数量，失败日志记录解析类型、位置及上游错误元数据，不记录提示词正文或密钥。

提示词位置匹配由 `shared/prompt-roles.js` 统一处理，兼容空格、全角符号及“场景(1)”“A+(1)”等明确等价写法，统一为工作区的标准位置名称。实时预览与完整响应解析使用同一规则；只匹配本次请求的位置，不按返回数组顺序推断归属，归一化后的位置重复、未知位置、越出本次范围或位置缺失仍拒绝正式保存。分析请求的 JSON 示例使用本次首个位置，并明确要求 `role` 保留标准名称。

提示词各部分均使用模型返回内容，默认模板与自定义要求仅作为分析输入，不在保存或生图时覆盖第三、第四部分，也不为缺失部分回填模板。产品实拍图可留空：有实拍图时，每次生图均传入该产品全部实拍图，主图与列表按顺序去重，不按分析返回或历史保存的视角编号筛选，不附带对标图；没有实拍图时传入该产品全部卡片的对标图，按卡片顺序去重，并标明每张附图所属位置、当前生成位置及其对应的附图编号，其他位置仅作整套风格、配色和产品信息参考。当前卡片没有对标图时如实注明并按提示词设计，整套也没有对标图时按文本生成。图片列表及其实拍／参考性质在入队时冻结；无实拍图的分析快照保留全部卡片，分析和提示词写入仍仅处理所选位置，依赖生图使用该快照中的全部实拍图或整套参考图。分析要求返回全部实拍图编号，旧编号仍兼容读取但不影响附图范围。参考图说明只在平台请求中添加，不改写已保存的提示词。

豆包咨询 `POST /api/assistant/chat` 在请求体指定 `stream: true` 后直接返回 SSE，先发送 `start`，再逐个转发上游 `response.output_text.delta` 为 `delta`；最终文本校正使用 `snapshot`，保存完成发送 `done`，错误发送 `error`。响应头立即刷新，关闭代理缓冲并发送保活注释；写入服从 socket 背压。HTTP 响应开始后的错误通过终止事件传递，开始前的验证错误保留 JSON 与 HTTP 状态。未指定流式的旧客户端仍接收 JSON。部分回复约每 400ms 保存一次，停止或断线时立即保存内存中的最新内容；轮次条件防止旧流覆盖重试。前端用 Fetch 流解码 UTF-8/SSE，按对话和消息 ID 更新，再由 React Markdown 与 GFM 渲染，跳过原始 HTML 并过滤危险链接。

## 持久化模型

新上传的图片在素材规范化时按实际文件字节数判断：大于 6×1024×1024 字节才压缩为严格小于该值的 WebP，小于或等于该值保留原始字节与格式。实拍图、参考图、表格粘贴及 XLSX 图片共用此入口，原有单张 40MB 输入限制仍生效。压缩保留透明背景、动画和宽高比例，先调整编码质量，仍超限时再缩小尺寸；解码复用本机图片处理并发池，在数据库写事务之前完成。现有素材地址不重新编码，平台返回的生成结果沿用原始保存流程。

- `workspace`：规则、界面表格快照、暂停和模型配置；历史并发字段仅为旧页面与备份兼容保留，执行时不使用。凭据单独加密保存。
- `products`：每个产品一条聚合记录，图片位置、提示词版本和结果历史暂存 JSON 文本，产品编号有数据库唯一约束。
- `jobs`：每次执行的冻结输入、依赖、阶段、平台 ID、到期时间、租约及领取者；活跃位置和整套任务有唯一索引。
- `job_attempts`：领取执行记录、阶段、结果与错误。
- `commands`：有指纹的操作 ID，重复相同命令返回原结果；相同 ID 配不同内容会拒绝。
- `assets`：素材哈希、MIME、字节数；文件放在独立持久目录，数据库与工作区只存素材地址。
- `assistant_conversations`：按产品、卡片区分的豆包对话，保存标题及当前选中的历史对话。
- `assistant_turns`：用户问题、模型回复、模型名称和完成/失败/中断状态；消息 ID 防止重复提交，执行轮次防止旧请求覆盖重试结果。重启时保留未完成的问题并标记中断，等待手动处理。
- `schema_migrations`：迁移版本及校验和；已执行文件不可修改，只能追加迁移。

产品采用 JSON 文本 聚合是这一阶段的有意取舍，避免同时重写全部旧业务规则。图片二进制已移出 JSON 文本；任务、尝试和幂等命令是独立表。若历史规模扩大，应通过新迁移将提示词和图片版本拆为明细表，而非继续扩大聚合。

SQLite 使用 WAL、FULL 同步和外键约束。数据库操作串行执行，写事务使用 BEGIN IMMEDIATE；这只串行化短暂的数据写入，不限制生图接口并发。无需单独安装数据库服务。完整文件备份应先停止应用，再复制整个 data 目录和 .env；运行中不可只复制 workspace.sqlite 而漏掉 WAL。

## 状态与付费边界

1. 创建命令与任务在同一事务中提交，Worker 只能领取已持久化任务。
2. 生图与查询阶段超时 180 秒，租约 240 秒；整套分析采用流式 Chat 响应，总超时 600 秒，租约 660 秒。租约始终长于外部调用超时，避免仍在执行的分析被提前判为中断。SQLite 写事务保证任务领取互斥；平台网络调用在事务之外并发执行，不设置全站、工作区或成员的固定网络并发上限。
3. 调用整套分析前先保存 `analyzing`；调用生图前先保存 `submitting`。
4. 平台返回 ID 后保存 `remote_id`，后续只查询原任务；查询、下载和失败重试不创建新的付费生图提交。
5. 查询未完成时保存进度并延迟派发。按 `due_at` 排序，避免较早的长任务挤占所有新任务。
6. 平台成功后先将图片保存到素材存储，再通过事务保存版本和任务完成状态。以 `jobId` 去重结果。
7. 整套分析失败会阻止依赖生图。整套结果需完整 10 个位置才允许生图。
8. 过期领取如已有平台 ID，则继续查询；如停在分析或提交阶段且没有 ID，则进入 `interrupted`，需要核对。没有平台幂等能力时，无法保证远端付费调用恰好一次。
9. 取消状态提交后立即发送本地 AbortSignal，终止正在进行的分析、提交、查询或下载；取消整套分析同时取消依赖它的待执行生图任务。平台已受理的任务可能仍继续执行。若取消与返回 ID 竞争，仍记录已收到的 ID，但不写入新图片版本。
10. 用户明确确认“平台未受理”，或提供原平台 ID，才可解除未知状态。分析没有可查询 ID，需用户判断是否允许再次执行。

执行器连续领取所有已经到期且依赖完成的任务，领取后立即并发执行，逐次让出事件循环以保持 HTTP 和取消操作可响应；不会等待已有平台请求完成再领取下一项。领取互斥、暂停、依赖、租约、幂等命令和未知付费提交边界继续生效。旧工作区 `concurrency`、`promptConcurrency`、`queryConcurrency` 字段及旧网络上限环境变量不再参与执行；兼容接口 `/api/execution/limits` 返回三个 `null` 表示无限制。

平台明确返回可重试的 HTTP 429 后，最多自动退避三次，任务保留自己的到期时间；冷却仅作用于该工作区、当前加密凭据版本、平台和模型。更换凭据后新请求不会受旧请求的冷却影响，其他工作区不受连带影响。迁移 016 重建冷却表，清除无法确定凭据归属的旧全局冷却，任务及其重试时间保留。限流记录只保存加密凭据版本的摘要，不保存明文 Key。`EXECUTION_PROFILE=local|small` 仅决定本机分析图片预处理分别最多 2／1 路；缩略图和数据库写入继续保留各自的资源保护，这些设置不限制模型网络请求。

查询或下载的临时失败最多连续自动尝试 5 次，并指数退避；失败后用户可继续原任务。平台明确失败不自动重复生图。网络、HTTP 5xx 或异常响应在付费提交边界采取保守核对策略。

## 编辑与展示一致性

编辑接口只接受可编辑字段及其旧值。任务状态、生成历史和平台 ID 不接受浏览器回写。普通资料按服务器事务提交顺序保存，同字段最后提交生效，不向用户弹出同步冲突确认。表格提交细化到单元格，兼容旧页面的整表快照并展开差异；格式、缓存和内部标识变化不会把旧文本覆盖回去。

轮询和推送刷新时保留未提交的真实编辑，客户端草稿、同步基线与服务端响应独立复制。执行输入在入队时冻结；分析过程中修改提示词时，新分析结果进入历史。表格回填由客户端消费结果完成，回填失败不影响已保存任务和结果。

`workspace_activity` 在资料保存的同一事务中记录登录身份、服务器时间、产品／图片位置／单元格及修改前后内容；只记录实际内容变化，忽略缩略图、图片内部标识、样式缓存和首次自动初始化表格。`GET /api/workspace/activity` 在当前工作区内按自增 ID 倒序返回最近 100 条，不提供旧记录分页；前端升序显示，最新记录在底部。仅限制读取和展示数量，不清理数据库旧记录。操作历史只读，不增加逐字段恢复界面。

当前单进程服务通过工作区独立的 `/api/workspace/events` SSE 推送保存完成通知和选区状态；内容仍通过增量接口读取，断线重连主动核对最新状态。选区通过 `/api/workspace/presence` 提交，身份取自会话，每个标签页独立标识；60ms 合并移动、10秒心跳、30秒过期，连接关闭或离开表格后清除。选区只驻留内存，不写操作历史。事件流持续复核成员权限与账号范围，多实例部署需共享事件和在线状态。

生产备份将素材地址转成图片数据，方便跨服务器迁移。导入只允许空工作区；保留历史和选图，未完成旧任务停止，不自动重新付费执行。原 IndexedDB 数据保留不删除。

## 访问与部署边界

全局账号与工作区成员身份分离：一个账号可加入多个空间，在各空间分别拥有所有者、编辑者或查看者角色。`accounts.ts` 管理全局凭据和会话，`members.ts` 管理空间成员，`invitations.ts` 管理单次邀请兑换，`workspace-directory.ts` 管理空间生命周期和成员上下文。HTTP 适配分别放在 `member-routes.ts` 和 `workspace-routes.ts`。普通业务写请求默认需要当前空间编辑权限；所有者接口标记 `config.permission: "manage"`，全局空间列表、创建及个人操作标记 `config.accountOnly: true`，仅要求有效账号。所有者写事务重新验证角色，所有权转让、成员状态和邀请兑换均原子提交。详细契约见 [账号、工作区与协作权限](accounts.md)。

`workspaces.ts` 装配带不可变工作区范围的 Repository、Assets 和 Workflows，HTTP 请求和 Worker 使用相同范围；`workspace-workers.ts` 每秒只唤醒有到期任务或过期租约的团队，不为每个空工作区创建轮询定时器。SQLite 采用共享数据库中的工作区列隔离：产品、任务、成员、素材、命令、对话、增量修订号和删除标记均属于工作区。素材读取和缩略图磁盘缓存命中前均校验所属团队，新增团队素材 ID 包含工作区命名空间。产品 ID 冲突不能覆盖其他团队资料，幂等命令按工作区区分；任务领取、过期恢复和暂停仅作用于当前团队。

前端记录本页会话的工作区范围，请求头和分析 SSE 地址携带预期范围。同一浏览器切换账号后，服务端在业务处理前拒绝旧页面的范围，防止旧草稿写入另一个团队。素材响应禁止浏览器持久缓存，登录和退出时请求清除缓存；新团队不自动导入浏览器旧工作区。

12 小时会话持久化在 SQLite，仅保存随机令牌的哈希；Cookie 使用 HttpOnly、SameSite=Strict，HTTPS（含可信代理）增加 Secure，并在会话读取时升级已有 Cookie。`REQUIRE_HTTPS` 默认 `false`，本机、局域网、Docker 和公网均允许 HTTP；开启后才在解析密码前拒绝 HTTP 业务请求。前端通过公开、无 Cookie、无缓存的 `transport-policy` 接口读取同一运行时开关，改配置并重启即可生效，无需重建前端。仅强制模式启用 HSTS；关闭时 HTTPS 清除该策略。HTTPS 可使用应用证书或明确配置的可信代理，详见 [登录与 HTTPS](transport-security.md)。全局账号状态与当前空间成员角色每次请求重新读取。成员角色变更、禁用和移除只作用于本空间，重发邀请只撤销旧链接；修改或部署恢复个人密码撤销其全部全局登录；重启保留未过期会话，APP_PASSWORD 变化时撤销默认管理员会话。API、素材和 SSE 均需会话，静态页面公开，写请求限制为同源协议与主机。邀请令牌只在生成时返回明文，分享链接使用 URL fragment，激活通过 POST 提交；令牌在数据库中哈希保存，7 天到期、使用后删除。源码 Compose 默认只绑定本机 3001 端口；服务器打包与域名代理使用本地 `docker:pack`、`docker:deploy` 流程，见 [Docker 部署](docker-deployment.md)。

任务额度独立于平台账单，按工作区、成员和北京时间自然月仅统计成功保存的图片任务，提示词分析和豆包对话不计数。`account-usage.ts` 在入队/重试事务检查已成功数与待完成图片数，防止并发越额；只有 Worker 保存图片并完成任务的事务才写入成功明细和月统计，以任务 ID 去重。失败或取消不计用量并释放容量，查询、下载恢复与自动重试不重复计数。迁移 010 从历史成功图片重建统计，011 保留这些明细的原空间归属并拆分全局身份与成员关系。生成任务在 payload 记录创建者与最近重试者，成员删除保留历史与用户名墓碑。页面额度输入框暂时禁用，新成员默认不限。

密钥不返回浏览器，不进入备份和请求日志。加密主密钥从环境变量提供，必须独立备份；丢失后无法解密原平台密钥。素材与数据库必须一起备份。

豆包对话模型、运行方式和生图节点保存在工作区文档中，仅所有者可修改。生图模型、比例、分辨率、GPT 尺寸与质量按 `member_generation_settings(workspace_id,account_id)` 保存，由 `member-generation-settings.ts` 合并读取，共享字段始终以工作区为准。迁移 017 为既有成员复制原参数；018 采用当前所有者原有的共享字段并清理个人记录中的共享字段，保留共用凭据和已入队快照。API 密钥仍保存在工作区加密凭据列，仅所有者可修改。任务入队在同一事务合并共享配置与发起人的生图参数并冻结到 `job.config`；豆包咨询使用工作区对话模型。个人生图配置记录不写入工作区文档同步和页面业务备份，完整数据库备份保留它。

迁移 019 将所有已有工作区（含归档工作区）的豆包对话及分析模型一次性初始化为 `doubao-seed-2-1-pro-260915`，覆盖此前的其他模型或 Endpoint ID；不改动密钥、个人生图参数及任务配置快照。新工作区沿用相同默认模型。迁移记录确保后续启动保留所有者重新选择的模型。模型配置页面仅提供共享对话模型，运行方式与生图节点不渲染、不随表单提交，保存时沿用已有值；接口的所有者权限和字段兼容性保留。

结果下载限制为 HTTPS、公共 IP、最多 4 跳和 40MB；校验后的 DNS 地址固定到 HTTPS 连接，避免二次解析。仅允许 PNG、JPEG、WebP、GIF 的基础格式签名。部署环境仍应限制对内部服务的出站访问。
