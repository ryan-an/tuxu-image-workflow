# 低带宽部署与加载

首屏分两步读取数据：`GET /api/workspace/startup` 只返回产品摘要、设置、同步游标和必要的任务状态；页面先显示导航与产品列表，再通过 `/api/workspace/products?ids=...` 读取当前产品详情。切换产品时才读取另一个产品，搜索和翻页使用轻量摘要，不预下载其他产品的提示词、图片历史和整套分析历史。

工作区启动、保存及增量同步均使用精简视图。未加载的产品不参加编辑差异计算，未读取的表格不会被当成空表保存；后台保存和多页面协作继续使用原有细粒度编辑、同步游标和权限校验。任务状态只保留每个位置的最新任务、仍在执行或待核对的任务，以及其依赖。任务明细在打开时调用现有分页接口，每页 50 条，不传输执行时冻结的产品副本和上游完整响应。历史记录仍保存在数据库中。

完整表格在打开表格、首次需要回填或导出时读取；表格视图和跨产品批量操作会先补齐产品详情。工作流备份单独读取完整工作区，继续包含所有历史及图片，不使用首屏的摘要数据。产品详情读取不推进全局游标，以免漏掉读取期间其他产品的变化。

Fastify 自动为超过 1 KB 的 JSON、JavaScript、CSS 和 HTML 响应协商 Brotli 或 gzip 压缩。Brotli 质量设为 4，gzip 设为 6，兼顾较低配置服务器的 CPU。图片及 SSE 不使用此文本压缩。图片卡片、历史小图、侧栏和只读表格使用按可见区域加载的 WebP 缩略图；查看大图和导出仍使用原图。

Vite 生成的带内容哈希的静态资源使用 `public, max-age=31536000, immutable`，新版本的文件名改变后自动读取新文件。HTML、业务 API 和需要权限的图片保留原有不持久缓存策略。开发者工具中的 **Disable cache** 会主动跳过浏览器缓存；检查正常重复访问时需要取消勾选，它不影响服务器压缩和首屏数据精简。

更新部署需要包含新增依赖和前后端构建：

```sh
npm ci
npm test
npm run build
# 重新启动生产应用进程
```

服务器部署使用 `npm run docker:pack` 生成运行包，再按 [Docker 部署](docker-deployment.md) 执行 `docker:deploy`。已有数据库、素材和 `.env` 继续保留，无需清空数据。

验证时在 Network 中检查：

- 启动使用 `workspace/startup` 和当前产品详情，而不是全量工作区接口。
- JSON、JS、CSS 响应有 `Content-Encoding: br` 或 `gzip`，以及 `Vary: Accept-Encoding`。
- 当前产品详情到达之前，产品列表和设置可以使用；加载失败时可点击重试。
- 任务历史仅在打开任务明细时按页请求；打开表格、备份等操作才读取相应完整数据。
- 正常刷新时哈希静态资源命中缓存；重新部署后 HTML 引用新文件。

自动测试使用隔离数据库、24 个带较长提示词历史的产品和 181 个历史任务。该夹具的原始全量工作区约 6.15 MB；启动摘要约 34.6 KB，gzip 后约 9 KB。这只是该测试数据的启动接口体积，不代表线上整个页面的加载时间或总流量。实际速度仍受服务器出口带宽、并发访问和当前产品数据量影响。
