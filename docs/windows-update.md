# Windows 便携版更新

以后更新已有 Windows 程序，使用每次发布的 `tuxu-update-windows-x64-v版本号.exe`，无需解压 ZIP 或手动复制数据。首次部署、从 Docker 迁移仍使用完整便携 ZIP，迁移步骤见[数据迁移指南](data-migration.md)。

## 日常更新

1. 保存网页上的编辑，等待正在生成的任务结束；右键 Windows 右下角图序托盘图标，选择「退出图序并停止服务」，或在窗口「更多」中退出。叉掉窗口只会隐藏到托盘，不会停止服务；旧命令行版本可用 Ctrl+C 停止。
2. 下载新版更新 EXE，双击运行。在窗口的「程序目录」点击「选择」，选中原来的图序程序目录，即里面有 `图序.exe`、`runtime`、`data` 和 `.env` 的目录；确认路径后点击右下角「开始更新」。整个流程不弹命令行窗口。
3. 窗口会显示检查、备份和替换阶段。等待显示“更新完成”，然后双击原目录的 `图序.exe`。浏览器刷新后使用新版，原来的访问地址、账号、图片、工作区和平台密钥继续使用。

更新工具自带完整程序与运行依赖，不需要另外安装 Node.js、Docker 或解压工具，也不需要复制 EXE 到原程序目录。它不会自动下载新版本；每次收到新版更新 EXE 后手动运行即可。

## 数据与备份

### 主动备份

从托盘退出图序并停止服务后，打开更新 EXE，选择原程序目录，点击左下角「备份数据」。等待显示“备份完成”后可以关闭工具，或继续更新。单独备份不会安装更新，也不要求更新工具版本高于当前程序。

手动快照位于 `data/backups/manual-时间-标识/`，包含 `data/`、原 `.env` 和状态文件 `update.json`，不复制程序文件。状态记录当前安装的版本、构建标识及 `kind: manual`。备份和更新期间请保持窗口打开，等待完成后再启动图序。

更新只替换程序目录中的 `dist`、`build-server`、`node_modules`、`runtime`、`scripts`、启动入口、图标、程序元信息和附带说明。旧版根目录的「第三方许可」目录仅在存在时收进程序备份，不要求原程序或更新包包含此目录；替换失败时会一并恢复。组件声明统一放在 `runtime/licenses/`，仅适用于所列第三方组件，不表示图序自有代码开源。`data/` 与原 `.env` 留在原位置，其他自行添加的根目录文件也保留。`CREDENTIAL_SECRET` 不会重新生成。

新版启动时兼容旧数据库迁移记录的 Windows / Linux 换行格式差异，保留既有迁移记录并继续执行新增迁移。若遇到“已执行迁移 001.sql 内容发生变化”，从托盘退出服务后重新运行包含此修复的更新 EXE，再启动图序；不需要删除数据库、修改迁移记录或重新生成 `.env`。

更新前，工具会在 `data/backups/update-时间-标识/` 保存：

```text
data/         # 更新前的数据库、WAL/SHM、图片、日志和 data 内的证书
.env          # 原配置和加密主密钥
program/      # 被替换的旧程序文件
update.json   # 更新状态与构建标识，不包含密码或密钥
```

自动快照不重复复制 `data/backups/` 中已有备份和 `data/.update-work/` 中的更新临时文件，避免备份自身。

默认只保留最近 **2 份成功备份，手动与自动更新备份合计计算**。手动备份完成后，或自动备份完成且程序替换成功后，才清理更早的成功备份；本次备份始终保留。也会整理工具能识别的旧成功更新备份。连续手动备份可能清理旧更新备份及其中的旧程序，需要长期保留的重要快照请提前另存到其他设备。

更新失败、恢复未完成、状态缺失或无法识别的备份，以及自行创建的备份目录，不自动删除，因此异常备份可能使总数超过 2 份。包含符号链接或重定向目录的旧备份不清理；文件占用或权限问题导致清理失败时，窗口提示人工处理，程序更新仍视为成功。失败的更新不会触发旧备份清理。

这仍是完整复制：更新期间可能短暂同时存在 3 份或更多快照，需要为新备份留足磁盘空间。快照与原数据在同一磁盘，仍建议定期把完整 `data/` 和 `.env` 另存到其他设备。

工具会检查目标是否为图序 Windows 目录，拒绝更新正在运行的程序、覆盖更新包之外的数据位置或安装更旧的版本；同版本重复打包用构建标识区分。已经存在数据库却缺少原 `.env` 或有效加密主密钥时，必须先恢复原配置。若曾把数据库、素材或证书配置到 `data` 外部，先按迁移说明整理路径。

## 更新失败与回退

释放或备份失败时不会替换程序文件；替换途中发生错误时，工具尝试自动恢复刚刚移动的旧程序。原业务数据和 `.env` 不参与替换。看到错误提示后按提示处理，未显示完成前不要启动程序。

更新工具完成后不会自动启动新版，数据库迁移由下一次启动执行。暂不提供客户自助恢复入口。若需要恢复数据或回退版本，请保留当前数据、配置和所需备份，并联系维护者处理。

断电、强制结束更新工具或磁盘故障不保证能自动恢复。保留更新备份；若提示“恢复未完成”，请停止操作并联系维护者。

## 维护者

只打更新包，在 Windows x64 Node.js 24 环境执行：

```powershell
npm run windows:pack:update
```

命令会先构建最新程序，再生成 `artifacts/windows/tuxu-update-windows-x64-v版本号.exe` 及其 `.sha256` 文件；不会生成或覆盖独立部署 ZIP。EXE 内嵌的程序载荷会在临时目录打包，成功后清理，因此更新包仍包含完整运行依赖，客户使用时无需下载组件。

此命令使用当前版本号，不自动递增；需要新版本号时先运行 `npm run release -- patch --title "本次更新主题" --note "本次变化"`。

如果原更新 EXE 正在运行，先关闭它再覆盖，或指定其他输出目录：`npm run windows:pack:update -- --output artifacts/windows-next`。已有部署 ZIP 不会被删除。

`npm run windows:pack` 会同时生成完整 ZIP 和离线更新 EXE，每个文件各有 SHA256 校验文件。生成的更新 EXE 内嵌同一个 ZIP 并核对其 SHA256；只有程序文件允许进入更新载荷。每次打包生成独立 `buildId`，不修改 `.env` 或用户数据库。

便携包及更新工具测试见 [测试说明](../tests/README.md)，覆盖数据与主密钥保留、完整自动备份、运行中拒绝、缺少配置拒绝、降级拒绝及程序替换失败恢复。
